# irmf-tsl-compile

Compiles an IRMF **TSL** body — JavaScript that builds a three.js TSL node
graph — into a **standalone WGSL function** that the IRMF CLI slicers splice
into their existing WGSL footer.

```sh
npm ci
node src/cli.mjs --json --materials 3 examples/foo-tsl.irmf
```

## Why a compiler?

TSL is JavaScript, not shader text. It is evaluated at graph-build time and
lowered to WGSL (or GLSL) by three.js. The Go and Rust slicers already have
proven WGSL backends, so compiling TSL to a WGSL *function* and reusing those
backends is the lowest-risk integration.

The compiler uses three.js's `WGSLNodeBuilder` directly, with no GPU, no
canvas, and no renderer. The builder is imported from an internal path
(`three/src/renderers/webgpu/nodes/WGSLNodeBuilder.js`) because it is not part
of the public `three/webgpu` export list in r180. **This is an undocumented
API**, so the compiler is pinned to three.js `0.180.0` (see `package.json`).

## Output

A self-contained block with no `@group`/`@binding`/uniforms:

```wgsl
// generated by irmf-tsl-compile; three 0.180.0

fn mainModel4( xyz : vec3<f32> ) -> vec4<f32> { ... }
```

- 1–4 materials → `mainModel4` returning `vec4<f32>`.
- 5–9 materials → `mainModel9` returning `mat3x3<f32>` (column-major material
  order, matching the slicer footers).
- 10–16 materials → `mainModel16` returning `mat4x4<f32>`.
- Unused components are padded with `0.0`.

## CLI

```
irmf-tsl-compile [options] [file|-]

  --json               Emit a JSON result object.
  --check              Compile only; omit the generated source.
  --materials N        Material count (required for raw bodies).
  --entry NAME         Entry point name (default: from material count).
  --format function    Only "function" is supported.
  --target wgsl        Only "wgsl" is supported.
  --cache-dir DIR      Content-addressed cache.
  --timeout-ms N       Hard limit for the compile child (default 30000).
  --[no-]sandbox       Run the compile child with Node's permission model.
  --version            Print the three.js version.
```

JSON success shape:

```json
{
  "ok": true,
  "three": "0.180.0",
  "entry": "mainModel4",
  "materials": 3,
  "target": "wgsl",
  "format": "function",
  "source": "fn mainModel4(xyz: vec3<f32>) -> vec4<f32> { ... }",
  "warnings": [],
  "diagnostics": []
}
```

Failure: `{"ok": false, "diagnostics": [{"line": 12, "col": 4, "message": "..."}]}`
and exit code 1. `line` is 1-based relative to the TSL body (after `}*/`).

## Security model

TSL bodies are arbitrary JavaScript. The compiler:

- shadows `fetch`, `XMLHttpRequest`, `WebSocket`, `EventSource`,
  `importScripts`, `require`, and `process` inside the evaluated body;
- rejects `export` and dynamic `import()`;
- runs the evaluation in a child process with a timeout, and, by default,
  Node's permission model (`--permission --allow-fs-read=<compiler dir>`), so
  the body cannot read or write files outside the compiler tree;
- performs no network access of its own.

These are **guardrails, not a hardened sandbox**. Node's permission model does
not block network access, and a determined body can still reach `globalThis`.
Treat untrusted TSL as untrusted code. `encoding: "gpg"` protects
confidentiality only and is not an execution boundary.

## TSL authoring notes

See `../../docs/tsl-spike-results.md` and the IRMF spec. Key rules:

- Use `.toVar()` for arrays that are indexed dynamically.
- Give nested `Loop`s distinct `name`s.
- Loop indices are `i32`; cast with `float(i)` before math.
- `Fn(([xyz]) => [m0, m1])` array returns are unwrapped by the compiler; plain
  functions work too.
